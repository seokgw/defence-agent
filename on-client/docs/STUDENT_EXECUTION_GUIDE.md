# 학생 실행 설명서 및 시스템 구성

> 이 문서는 현재 저장소의 실행 설정과 단계별 인터페이스 계약을 바탕으로 작성했습니다. 문서 작성 AI는 이 PC에서 명령·앱·브라우저·외부 서비스를 실행하지 않았습니다. 따라서 실제 시작 성공, 계정 연결, 접근 판정, AI 호출, OSV 응답은 이 문서만으로 확인된 것으로 보지 않습니다.

## 1. 목적과 기능

이 프로젝트는 브라우저에서 로컬 보안 Agent UI를 열고, 제공 서버와 학생 렌더러를 통해 계정·기기·세션, 업무 앱 접근 판정, 보안 기록, AI 연결·사건 설명, 설치 패키지 취약점 조회 결과를 표시하는 수업용 프로젝트입니다. 메뉴와 실제 데이터 기능의 일부는 제공 코드 및 운영 측 연결 설정에 의존합니다. 서버 시작 메시지나 예제 자료는 실제 계정 연결 또는 실제 보안 기능 성공을 의미하지 않습니다.

## 2. 실행 환경과 폴더

| 항목 | 프로젝트에서 확인한 내용 |
|---|---|
| 실행 환경 | Windows에서 제공된 PowerShell 실행 스크립트를 사용하는 절차가 문서화되어 있습니다. 다른 운영체제에서의 실행은 이 안내로 확인되지 않았습니다. |
| Node.js | `package.json`의 `engines.node`는 `24.19.0`입니다. 이는 프로젝트가 선언한 버전이며, 이 문서를 작성하는 동안 PC에 설치된 버전이나 실제 실행 결과를 확인한 것은 아닙니다. PowerShell에서 `node --version`으로 직접 확인하세요. |
| npm 의존성 | `package.json`에 `dependencies`/`devDependencies`가 선언되어 있지 않습니다. 따라서 이 안내는 `npm install`을 실행하라고 요구하지 않습니다. |

| 기본 브라우저 주소 | `http://127.0.0.1:5189/` (기본 포트로 안내된 주소. 다른 포트를 지정했다면 그 포트로 바꿉니다.) |

## 3. 시작·종료·재실행

1. 파일 탐색기에서 프로젝트 안의 **`on-client` 폴더**를 엽니다.
2. 해당 폴더의 주소 표시줄에 `powershell`을 입력하고 Enter를 눌러 그 위치에서 PowerShell을 엽니다. 현재 위치가 `on-client`인지 확인합니다.
3. 버전 확인이 필요하면 다음을 실행합니다. 출력은 본인 PC의 실제 설치 버전입니다.

   ```powershell
   node --version
   ```

   프로젝트 선언 버전은 `v24.19.0`입니다. 출력이 다르면 임의로 환경을 바꾸기보다 담당자 안내를 확인하세요.

4. 다음 시작 명령을 실행합니다.

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
   ```

5. 정상 시작의 기대 신호는 실행 도구가 서버 시작을 알리고 로컬 주소를 안내하는 것입니다. 기본 주소는 `http://127.0.0.1:5189/`입니다. 이 안내서는 실제 터미널 출력을 확인한 것이 아니므로, 정확한 로그 문구나 이번 PC에서의 시작 성공을 보증하지 않습니다. 주소가 안내되지 않거나 오류가 나오면 성공으로 간주하지 말고 오류 문구를 확인하세요.
6. 브라우저에서 `http://127.0.0.1:5189/`을 엽니다. 서버를 실행한 PowerShell 창은 앱을 사용하는 동안 닫지 않습니다.
7. 종료할 때는 실행 중인 그 PowerShell 창에서 `Ctrl+C`를 누릅니다. 다시 실행할 때는 같은 `on-client` 폴더에서 같은 시작 명령을 실행합니다. 기존 작업 폴더나 Git 기록을 삭제·초기화하지 않습니다.

기본 포트 `5189`가 이미 사용 중이라는 시작 오류가 나오면 제공 스크립트의 포트 옵션을 사용할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190
```

이 경우 브라우저 주소는 `http://127.0.0.1:5190/`입니다. 먼저 기존 프로그램을 임의로 종료하지 마세요.

선택 사항인 학생 파일 문법 확인 명령은 다음과 같습니다. `package.json`의 `check` 스크립트는 이 명령과 같은 `node --check student/extension.mjs` 검사를 실행합니다. 문법 확인은 앱 동작·외부 연결·과제 통과를 증명하지 않습니다.

```powershell
node --check .\student\extension.mjs
```

## 4. 글로 쓴 시스템 구성도

```text
[사용자 브라우저]
  public/index.html + public/app.js
  - 제공 메뉴, 사용자 입력, 로컬 API 요청, 화면 갱신
  - student/extension.mjs 렌더러를 호출해 학생 표시 영역을 구성
             │ HTTP (기본 로컬 주소 127.0.0.1:5189)
             ▼
[로컬 앱 서버: src/server.mjs]
  ├─ 기본/예제 엔진 및 제공 서비스 연결
  ├─ (설정·권한이 준비된 경우) 접근 제어·기기·세션·감사 기록 및 저장된 XDR 경보의 서버 경로
  ├─ (별도 계정 연결·앱 승인·권한이 준비된 경우) 서버 측 AI 서비스 → 수업용 AI 게이트웨이
  └─ (허용된 공개 패키지가 설정된 경우) package-lock 설치 버전 확인 → OSV 공개 조회 서비스
```

브라우저는 로컬 앱 서버와 통신하며 AI 회사의 비밀 키를 직접 받거나 보관하는 구조로 안내되어 있지 않습니다. AI 모델 목록 점검과 특정 보안 기록의 AI 설명은 별도 동작입니다. OSV는 공개 취약점 정보 조회이고 악성코드 탐지·치료가 아닙니다. SDP/XDR, AI 게이트웨이, 공개 패키지 조회는 운영 측 설정·응답이 없거나 확인 불가할 수 있습니다. 위 구성도는 코드·문서에 나타난 경계를 설명하며 모든 외부 연결이 현재 PC에서 성공한다는 뜻은 아닙니다.

## 5. 제공 코드와 학생 코드의 경계

| 영역 | 실제 경로 | 역할과 경계 |
|---|---|---|
| 제공 UI | `public/index.html`, `public/app.js`, `public/`의 보기 모듈 | 메뉴·입력·버튼·서버 요청·자료를 받아 렌더러를 다시 호출하는 UI 경계입니다. 21단계에서는 수정하지 않습니다. |
| 제공 서버 | `src/server.mjs` | 로컬 HTTP 서버와 서비스 연결의 진입점입니다. 학생 안내서는 서버 코드를 바꾸거나 인증 경로를 추가하지 않습니다. |
| 제공 연결·엔진 | `src/connection/`, `src/engine/`, `src/actions/` | 설정된 계정/SDP 엔진 및 서버 측 처리를 담당하는 모듈입니다. 운영자 발급 설정·권한 없이는 실제 연결을 보장하지 않습니다. |
| 제공 AI 서비스 | `src/ai/`, `src/learner-support/` | 서버 측 AI 연결·모델 점검·설명 서비스 경계입니다. 모델 목록 응답은 사건 설명 성공이 아닙니다. |
| 제공 패키지 조회 | `src/vulnerabilities/osv.mjs`, `src/vulnerabilities/project-scan.mjs` | 정확한 lockfile 설치 버전과 승인된 공개 패키지를 조회합니다. 허용 목록이 비면 조회 대상이 없을 수 있으며, 실패/부분 확인은 취약점 없음과 다릅니다. |
| 학생 렌더링 계약 | `student/extension.mjs`의 `createStudentView()`가 제공하는 렌더 함수들 | 과제 단계별 학생 표시 영역을 구성하는 위치입니다. 이 단계의 문서 작성은 학생 렌더 코드나 제공 UI/서버를 변경하지 않습니다. |

과제에서 지정한 학생 함수 계약은 `renderIdentity`, `renderDecision`, `renderEvents`, `renderStatus`, `renderAiConnection`, `renderExplanation`, `renderAction`, `renderVulnerabilities`입니다. 이 문서는 해당 단계들의 목적을 설명하지만, **현재 파일 전체의 diff나 각 함수의 모든 동작을 재검증한 보고서는 아닙니다.** 특히 20단계 `renderVulnerabilities` 교체 후 diff 확인 결과는 이 문서 작성 시 확인되지 않았습니다. 커밋 전 함수가 계약을 구현하는지와 다른 함수가 바뀌지 않았는지 diff로 확인하세요.

## 6. 기능의 의미와 확인 범위

| 기능 | 사용자에게 보여 주는 범위 | 성공으로 과장하지 말아야 할 점 |
|---|---|---|
| 사용자·기기·세션 | 전달된 현재 사용자/기기/세션과 상태 | 세션 자료는 과거 전체 세션 목록이 아닐 수 있습니다. `unknown`은 확인 불가입니다. |
| 업무 앱 접근 판정 | 선택한 앱의 `allow`/`deny`/`challenge`/`unknown`, 사유·시각 | `allow`는 정책상 접근 허용이며 실제 업무 앱 접속 성공을 보장하지 않습니다. `challenge`는 추가 인증을 대신하지 않습니다. |
| 보안 기록·XDR | 현재 조회 범위에서 받은 본인 기록 및 저장된 경보 | 전체 로그나 실시간 전체 위협 탐지가 아닙니다. XDR 목록은 저장된 경보이며 화면 열기로 새 탐지가 되지 않습니다. 조회 범위/건수는 제공 UI가 표시할 수 있습니다. |
| AI 연결·사건 설명 | 연결 점검과 선택한 사건에 대한 별도 설명 | 모델 목록 점검만으로 사건 설명이 실행된 것이 아닙니다. 설명은 참고 정보이며 보안 사실은 원 기록·근거·연동 상태로 판단합니다. AI 설명은 조치를 실행하지 않습니다. |
| 설치 패키지 OSV 조회 | 서버가 허용한 공개 패키지의 실제 설치 버전과 당시 알려진 항목 | `none_found`는 해당 조회 범위·시각의 알려진 항목이 없다는 뜻이지, 패키지나 앱 전체가 안전하다는 보장이 아닙니다. `not_checked`, `not_configured`, `partial`, `unverifiable`은 취약점 없음이 아닙니다. 설치 패키지를 낮추거나 바꾸지 않습니다. |
| 보안 조치 상태 | 제안·사람 확인·서버 접수·결과 재조회·효과 관측 상태의 구분 | 현재 안내상 실제 연동 조치가 준비되지 않았고 지원 조치가 비어 있을 수 있습니다. 접수(ACK)는 효과 확인이 아닙니다. 실제 효과는 명시된 관측 결과로만 말합니다. |

## 7. 오류가 발생했을 때

| 증상 | 확인 순서 | 복구 경계 |
|---|---|---|
| `node`를 찾을 수 없거나 버전이 맞지 않음 | `on-client` PowerShell에서 `node --version` 실행, 프로젝트 선언 버전 `24.19.0`과 비교 | 설치·버전 변경은 담당자/수업 환경 안내를 따릅니다. |
| 실행 도구가 앱 폴더가 아니라고 하거나 서버가 시작되지 않음 | PowerShell 현재 위치가 실제 `on-client`인지, `tools\start-alekov.ps1` 파일이 있는지 확인하고 오류 전체를 읽습니다. | 기존 폴더를 지우지 않습니다. 오류가 해결되지 않으면 담당자에게 메시지만 전달합니다. |
| 포트 `5189` 사용 중 | 다른 프로그램을 종료하지 말고 위의 `-Port 5190` 실행 방법을 사용 | 브라우저 포트도 `5190`으로 일치시킵니다. |
| 시작 뒤 브라우저가 열리지 않음 | 터미널에 표시된 주소를 확인하고, 로컬 서버가 계속 실행 중인지 확인 | 시작 신호가 없거나 오류면 연결 성공으로 보지 않습니다. 터미널에서 `Ctrl+C`로 종료 후 원인을 확인하고 재실행합니다. |
| 계정 연결 또는 AI 연결이 `확인 불가`·권한 준비 중 | 앱의 해당 상태와 오류 코드를 확인합니다. 계정 연결, AI 앱 승인, 모델 점검은 각각 별도 단계입니다. | 같은 요청을 연속 반복하지 않습니다. 운영자 계정/권한/게이트 준비가 필요하면 담당자 확인을 기다립니다. 비밀값을 문서나 대화에 붙이지 않습니다. |
| 기록·기기·세션 조회 실패 또는 `CONTRACT_MISMATCH` | 실패와 정상 빈 목록을 구별하고 화면의 도움정보 및 안전한 오류 코드를 확인합니다. | 위쪽 제공 「다시 불러오기」를 사용자가 직접 누릅니다. 자동 재시도가 있었다고 가정하지 않습니다. 이전 자료를 현재 결과로 간주하지 않습니다. |
| 패키지 조회가 `not_configured` 또는 `not_checked` | 프로젝트 설정과 운영자가 허용한 공개 패키지 목록의 준비 상태를 확인합니다. | 목록을 임의로 늘리거나 비공개 패키지명을 외부로 보내지 않습니다. 조회 실패를 취약점 없음으로 기록하지 않습니다. |
| `partial` 또는 패키지별 `unverifiable` | 전체 상태와 각 패키지 상태를 따로 읽고, 이미 받은 취약점 ID가 있으면 함께 확인합니다. | 부분 조회 결과를 완전한 전체 조회로 표현하지 않습니다. OSV 조회를 위해 의존성 버전을 임의로 낮추지 않습니다. |

## 8. 미확인 사항

- 이 설명서를 작성하면서 Node 버전, 앱 시작 명령, 브라우저 화면, 서버 API, 외부 AI/SDP/OSV 통신을 실행해 확인하지 않았습니다.
- 새 PowerShell 창에서 시작·종료·재실행 절차를 직접 따라 하지 않았습니다.
- 기본 서버 시작의 실제 터미널 출력과 브라우저 화면은 미확인입니다.
- 20단계 `renderVulnerabilities` 교체 후 `git diff` 및 `git diff --check` 결과는 제공되지 않아 미확인입니다.
- 실제 학생 계정의 AI 연결·사건 설명 호출과 실제 SDP/XDR 이벤트 결과는 미확인입니다.
- 문서의 구성도는 코드 경계 설명이며 운영 환경의 네트워크 연결 성공을 인증하지 않습니다.

## 9. 21·22단계 커밋과 제출

1. 학생 문서와 이번 단계 변경을 같은 커밋에 포함합니다. 먼저 저장소 최상위에서 `git status --short`, `git diff --check`, 대상 파일의 `git diff`를 확인하고, 이미 준비 중인 변경은 내용을 확인해 보존합니다. 비밀 설정·키·토큰 파일과 무관한 파일은 추가하지 않습니다. 전체 변경을 무차별 추가하지 않습니다.
2. 과제 화면의 제출 방법을 따릅니다. 현재 안내상 21·22단계는 저장소 주소와 **실제 40자리** 커밋 해시를 과제 화면에 직접 입력합니다. 비공개 저장소를 공개로 바꿀 필요는 없습니다.
3. 비공개 커밋의 원문 묶음이 요구되면 해당 단계의 **「비공개 저장소 원문 준비 방법」**을 열고 **「원문 전달 도구 받기」**를 사용합니다. ZIP은 프로젝트 밖에 풀고 JSON을 저장할 새 폴더도 프로젝트 밖에 만듭니다.
4. 제출 프로젝트의 Git 최상위 폴더에서 PowerShell을 열고 과제 화면이 제공한 `student-source-cli.mjs` 명령을 사용합니다. 도구·출력 경로는 실제 PC 경로로 바꾸고 `--commit`에는 실제 제출 커밋의 40자리 값을 지정합니다. 도구 명령을 임의로 만들어 실행하지 마세요. 해당 도구는 커밋된 원문을 묶는 절차이며 학생 코드를 실행하거나 업로드하는 절차가 아닙니다.
5. 생성 JSON을 같은 단계의 **「비공개 저장소 원문 묶음」**에서 선택하고 저장소·커밋·단계를 다시 확인한 뒤 제출합니다. 원문 전달 완료와 AI 검토 통과는 서로 다릅니다. 원문 전달만 실패했다면 기존 접수를 유지하고 화면의 **「원문만 다시 보내기」** 절차를 사용합니다.

이 문서 작성 과정에서는 Git 명령, 커밋, 원문 묶음 생성, 포털 제출을 실행하지 않았습니다. 실제 도구 명령과 실제 커밋 값은 과제 화면과 본인 Git 출력에서 확인해야 합니다.
